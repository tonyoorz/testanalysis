# 商业问数产品架构对标（Snowflake/Genie/Fabric/Palantir/Spotter）

> 编译自 [[智能问数Agent全网深度调研-2026-08-03]] §5（L548–632）。证据等级 B（官方公开契约）/D；闭源内部实现不作推断。

## 核心问题
头部商业问数产品公开架构里，哪些机制是 Data-Agent 最值得复制的「治理与验证设计」？

## 关键结论

### Snowflake Cortex Analyst + Semantic Views（§5.1，L552–568）
- Semantic View 是**数据库 schema-level object**而非独立 prompt YAML；官方推荐新项目用 semantic views，旧 semantic model YAML 仅兼容保留（L559–560）。
- 定义 logical tables、facts、dimensions、metrics、relationships、derived metrics；API 支持多 semantic view、multi-turn，返回 text/suggestions/sql/warnings/confidence（L561–562）。
- **Routing Mode 优先 semantic SQL，不满足时回退 standard SQL**——不能把它描述成「只允许语义对象」（L563）。
- **最值得复制：VQR + Evaluation**（L566–568）：Verified Query 把问题与逻辑对象 SQL 配对并记录 `verified_by/verified_at`；评测时被选为 ground truth 的 VQ **临时从运行时上下文移除**再生成执行比对（防 exact-match 泄漏），同时追踪 accuracy、regression、latency——比 Data-Agent 的 semantic-frame golden 高一个层级，验证「真的算对没有」。

### Databricks Genie Agent（§5.2，L570–592）
- 组成：Unity Catalog 数据、example SQL、instructions、trusted assets、knowledge store（L577）。
- knowledge store 含 table/column 描述与同义词、curated datasets/hidden columns、prompt matching（format + entity matching）、join relationships、structured SQL expressions（L579–584）。
- **实体匹配存代表值**解决「Florida」vs `FL` 值语义差异；知识挖掘分析 metadata/主外键/点赞下载查询提出新 join 或 SQL expression，**须审核后入库**（L585）。
- 借鉴：候选维度维护受控 value dictionary；用户反馈转 proposal 不直写 Ontology；领域 scope 局部知识；成功分析沉淀 verified analysis template。

### Microsoft Fabric Data Agent + Fabric IQ Ontology（§5.3，L594–605）
- Orchestrator 选 warehouse/lakehouse/KQL/Power BI semantic model/ontology 等数据源工具；Power BI 走 DAX generation/validate/execute（L599）。
- Ontology 定义 entity types、properties、relationships、rules、constraints、data bindings，提供 graph representation 与 NL2Ontology query layer；强调 filters、joins、units、validity windows 与发布 Ontology 一致（L601）。
- **Ontology 仍 Preview 且官方 FAQ 明确暂不支持版本管理**——方向验证强，不是成熟完备的标准答案（L603）。
- 启示：**Ontology 要绑定可执行数据，query surface 直接面向业务概念**，不只是 Agent 的术语字典。

### Palantir AIP / Foundry Ontology（§5.4，L607–622）
- 关键不是聊天：Ontology 同时承载 object types、links、**actions、functions**；Functions repository 自动生成类型绑定，函数可读 object set、遍历 links、经 OntologyEditFunctions 改对象（L612）。
- pro-code Agent 模板打包 OSDK client + Ontology MCP + Agent logic，发布注册 Ontology binding 与 async function（L614）。
- 借鉴：**关系是类型化读取/动作接口而非展示图**；tool/action 绑定 Ontology capability；业务函数比任意 SQL 更适合跨领域操作。后续 testcase 生成与 Octane 写操作应走 `Ontology type → generated binding → function/action` 方向（L622）。

### ThoughtSpot Spotter（§5.5，L624–631）
- 不直接 text-to-SQL：NL → **relational search tokens** → governed semantic model 解析 join/ratio/growth/cohort → SQL；token 映射可展示、存储、管理员审核（L629）。
- 最值得学的不是营销的「准确率保证」，而是：**业务用户能看到并纠正语义 token，比只展示 SQL 更容易验证**——UI 应展示「指标/维度/范围/时间/比较组/快照」而非隐藏 reasoning（L631）。

## 操作要点
- 五家共同指向 [[60 Knowledge/Concepts/智能问数行业收敛方向-2026|行业收敛方向]]机制 3/4：Agent 不拥有事实解释权、反馈经审核沉淀。
- 落点：VQR → [[60 Knowledge/Concepts/Data-Agent工程路线P0-P1-P2|P1.3 Verified Analysis Repository]]；token UI → P1.4；value dictionary → P1.2；`verified_by/at` 与 provenance → [[60 Knowledge/Concepts/Data-Agent目标架构三合同|analysis_ref 合同]]、[[60 Knowledge/Concepts/ktx与Context-Build-Plane|Context Build Plane]]。
