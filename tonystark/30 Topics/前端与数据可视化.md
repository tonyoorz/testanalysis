# 前端与数据可视化

> 数据看板（Defect Explore）的设计、前端优化、AI Chat 集成。综合 5 篇知识页。

## 主题概述

本主题围绕 **Data-Agent（Octane 缺陷分析对话式 Agent）** 与 **vizion-lab（DTSV 数据分析平台）** 两个项目的前端可视化与支撑数据层展开，涵盖后端 NL2SQL/Agent 架构、数据库选型与迁移（SQLite→PostgreSQL）、Defect Explore 看板的视觉改版，以及独立前端项目 vizion-lab 的 UI/UX 与多模态 AI Chat 升级。这些内容共同说明了"数据可视化前端"背后依赖的数据供给链路（下载→清洗→存储→读取）与前端呈现规范（设计语言、组件规范、交互规范）如何协同演进。

## 核心知识

### Data-Agent 整体架构（前端可视化的数据供给基础）
- 技术栈：FastAPI 后端（`api/main.py`，默认端口 8100）+ Vite/React/TS 前端；规则模式为默认，配置 API Key 后可切换 LLM 增强模式（智谱 GLM / DeepSeek）。
- 核心处理流水线：**理解**（`term_resolver→entity_extractor→intent_detector`）→ **SQL生成**（3条候选路径）→ **多路径执行比对** → **自修正**（QueryFixer）→ **结果校验**（ResultValidator）→ **叙事生成**（Storyteller）。
- Ontology（`agent/ontology/objects/*.yaml`：defect/project/testcase/defect_history/manual_run/team）作为全局单一事实来源，驱动 schema、别名解析、业务规则，贯穿理解、生成、校验各层，是前端展示语义一致性的根基。
- NL2SQL 本质是模板填充：`NL2SQLEngine.query()`（`agent/sql_engine/generator.py:590`）通过 `DirectGenerator`/`DecomposedGenerator`/`PlanBasedGenerator` 生成3个候选SQL，`MultiPathExecutor` 比较 `data_signature` 判定 UNANIMOUS(0.95)/MAJORITY(0.80)/DISAGREE。
- 全链路支持规则回退（意图/实体提取纯正则、SQL模板化、code interpreter有 `_fallback_code`），可离线运行，保证前端在无 LLM 时仍有数据可展示。
- API 入口：`api/main.py` — `POST /api/agent/query`(`:320`)、`GET /api/agent/stream`(`:444`)、`/api/agent/feedback`(`:485`)。

### 数据层现状与 SQLite→PostgreSQL 迁移（前端读取的底层依赖）
- 项目存在两套下载器：`download/octane_downloader.py`（默认写数据库）与 `downloader7.py`（纯文件落地，无DB写入），字段定义一致（`DEFAULT_F_DEFECT_MAIN`/`DEFAULT_F_MANUALRUN` 均 40/30 字段），但 history 抓取 limit 存在差异（`downloader7.py` 单票 10000 vs `octane_downloader.py` 5000）。
- 读取策略为 **DB优先+文件回退**（`db_migration_config.py:14` 默认 `db_first`，`:20` 写入默认 `both`），`data_processor.py` 的 `load_defect_data/load_test_data` 均有回退逻辑；`defect_explore6.py:669` 主加载 `use_db=True` 但底层仍可能回退文件。部分模块（`data_processor.py:3298/3810`、`longrunner_analysis.py:93/289`）仍直接读 `history/*.json`，说明本地文件尚未完全成为纯备份。
- SQLite 与 PostgreSQL 字段名/数量基本一一对应（`octane_payloads`、`octane_defect_histories`、`octane_defects`、`octane_manual_runs`），但 PG 约束更严格：`octane_defects` 的 `defect_id/raw_json/fetched_at`、`octane_manual_runs` 的 `mr_id/raw_json/fetched_at`、`octane_payloads.year` 在 PG 中均为 NOT NULL，SQLite 当前可为空。
- 项目已具备 PG 支持代码基础：`requirements.txt:55`（psycopg）、`deploy/start_postgres.sh:1`、`init_postgres_db.py:1`；真正支持 PG 读取的是 `UnifiedDataLoader`（`unified_data_loader.py:526,773`），已做 smoke test 跑通（当前 PG 为空返回 0 行）。
- 迁移状态：字段兼容但数据尚未导入——defects（SQLite 15298 / PG 0）、manual_runs（SQLite 34333 / PG 0）、histories（SQLite 8493 / PG 0），需迁移数据并切换读取链路才能真正生效；`defect_explore`/`data_processor` 目前仍走 SQLite 读取路径（`data_processor.py:921`）。

### Defect Explore 看板视觉改造
- 最终锁定设计风格：**Amplitude + Mixpanel 产品分析仪表盘风格，叠加 Power BI 的信息层级规范**（依据用户页面"用户/公司活跃+趋势+左侧导航"结构，接近 Amplitude 的 Twilio Segment User Activity Dashboard 模板；Mixpanel 提供多视图切换导航；Power BI 补充信息密度规范）。
- 设计令牌（Design Tokens）：背景 `#F3F5F9`、卡片背景 `#FFFFFF`、边框 `#E6EAF0`；主文字 `#2B3340`、次文字 `#7A8393`；强调色蓝 `#42A5F5`、绿 `#3BB273`、粉 `#F4A7B9`；左侧深色导航宽度 `76-84px`。
- 组件规范：KPI卡（标题+说明+分隔线+3个大数字：日/周/月）；趋势卡（统一 legend 顶部横排、弱网格线、hover 同步）；筛选条（时间范围置首、其他过滤收纳为 chips）。
- 交互规范：首屏不滚动优先（关键四卡必须一屏可见）、数字可点击下钻到明细表、图表颜色全局固定映射（同指标永远同色）。
- 实施仅限单文件 `aianalysis/defect_explore_modern.py`，未改动 `defect_explore6.py` 或其他代码：
  - 配色/卡片样式：`:10`；布局结构（左侧深色导航+顶部 Product Usage 区+筛选条+2x2卡片）：`:243`；指标/趋势卡片：`:132`；时间周期筛选回调：`:394`。
  - 第二轮接入真实数据，复用 `defect_explore6` 同源 `data_processor.load_defect_data`，带无数据兜底：`:69`。
  - 校验：`python3 -m py_compile aianalysis/defect_explore_modern.py` 通过；启动 `python3 aianalysis/defect_explore_modern.py`，监听 `http://localhost:8056`。

### vizion-lab 前端与 AI Chat 多模态升级
- 技术栈：**React + Vite + shadcn/ui + Recharts + Tailwind CSS + Framer Motion**，已具备统一主题系统、暗色模式、KPI 卡片动画、可折叠侧边栏、AI 助手浮动面板。
- GitHub 远程仓库 `tonyoorz/vizion-lab` 持续被团队推进（先后领先 37/58 个提交），远程团队用 **DuckDB WASM**（`src/lib/duckdb/`）+ **Pyodide**（`src/lib/pyodide/client.ts`，浏览器端 Python 解释器）取代了本地新建的纯前端 `fileParser.ts` 方案，实现浏览器内 SQL 查询能力。
- 三 worker 并行改造内容：
  - 侧边栏 `DashboardSidebar.tsx`：分组标题（缺陷分析/测试分析/智能助手）、3px 活跃指示条、底部用户区、Logo 渐变光晕。
  - 新建 Header `DashboardHeader.tsx`：面包屑导航、全局搜索（⌘K）、通知铃铛、暗色切换。
  - KPI 卡片 `KPICards.tsx`：sparkline 迷你趋势图、800ms 数字动画、渐变顶部边框、hover 上浮阴影。
  - 页面切换动画 `Index.tsx`：250ms fade+slide 过渡。
